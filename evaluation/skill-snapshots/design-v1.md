# Design

Favor clear hierarchy, focused interactions, room to breathe, and concise copy. Let the product and task determine density and expression.

## Ground the direction

Inspect the existing interface and supplied references. Preserve established identity and behavior unless the request changes them. Match reference details when a faithful recreation is requested. For a local edit, follow the component system and keep the work focused on the affected area.

When choosing a new direction, inspect relevant rendered references; include a comparable workflow when building an app. State a brief direction connecting the user's main task to concrete choices in composition, typography, density, and imagery. Extract relationships from references: hierarchy, proportions, image treatment, and navigation. If a reference is unavailable, report the gap and label assumptions.

## Compose around the content

- **Choose the right structure.** A product page can lead with a compelling demonstration; an operational tool should expose the work and its controls. Choose sections from the content and journey. Recompose narrow layouts to keep the main task visible and useful comparisons intact.
- **Make priority visible.** Establish a clear focal area and reading order through placement, scale, contrast, and space. Keep secondary actions quieter. In a dense tool, prioritize the active task, exception, or selected object instead of enlarging everything.
- **Group by meaning.** Use shared alignment, proximity, headings, and dividers. Use cards for distinct objects or bounded interactions. Keep controls beside the content they affect; put each setting in one predictable place. Preserve useful density within groups and breathing room between them.
- **Use one visual language.** Choose a small, reusable set of type roles, spacing intervals, colors, and surface treatments. Make headings, body text, labels, and metadata distinct and readable. Let the product determine the palette and typography.
- **Make the content carry the identity.** Build with representative text and data. Source or create meaningful imagery early when the design depends on it; inspect its quality, crop, and mobile fit. Show the product or a useful demonstration where that explains it better than prose. Write labels and messages that help the user act.
- **Make interaction legible.** Build the requested interactions with relevant empty, loading, error, and success feedback. Use motion to explain changes, guide attention, or give feedback; keep it subordinate to the task and respect reduced motion.

## Inspect and revise

Render the interface and visually inspect it in the browser or screenshots. For a local edit, check affected components, states, and widths. For a new or redesigned surface, inspect desktop and narrow layouts and exercise the main journey, including relevant failure states and keyboard navigation. Check legibility, contrast, focus, alignment, wrapping, overflow, and whether the primary action is obvious.

Compare the result with the brief and inspected references. Fix the largest visible or behavioral mismatch, then repeat the affected check. Prioritize composition and usability before small decoration. Finish when the requested work passes these checks and known material defects within scope are resolved; report verification gaps.
